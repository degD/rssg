This post documents redged's static site generator, a deliberately minimal static site generator. It is a single Python script that transforms the HTML under posts into a static site in build.

I built it after trying Hugo, which felt overly complex for my use case.

Using the tool

It is not designed for general use. To use it, clone the source, replace posts and src with your own content, then run python3 build.py.

Adding a post

A post is an index.html inside a directory under posts, containing the post body as plain HTML.

Each post needs a corresponding entry in posts/_metadata.json. For this post:

{
    "title": "Blog",
    "date": "26/09/22",
    "post": "blog"
}

Every entry must have three fields:

  • title: the post title.
  • date: the date in YY/MM/DD format. Posts are sorted by it, newest first.
  • post: the name of the post's directory under posts.

How the build works

build.py generates the output from two kinds of templates:

  • A hardcoded template per post: each post is wrapped in a minimal HTML document and written to build/posts/<slug>/index.html.
  • src/index.html: the home page. Its <!-- {{POSTS-LIST}} --> marker is replaced with a list of all posts.
  • src/style.css: copied to build as-is. Any additional files under src need their own copy step in build.py.

deploy.sh copies the build output onto the pages branch of the codeberg repository and pushes it; codeberg serves that branch as the live site. See the site online.
